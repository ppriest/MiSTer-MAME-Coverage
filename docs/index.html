What this is

A comparison of the arcade machines MAME emulates with the ROM sets MiSTer FPGA cores can load, to show what is still missing on MiSTer. Everything on this page is computed by a Python script (source) and served as static files.

How it is built

  • MAME side. The -listxml output mamedev attaches to each release. A machine counts as arcade when it is runnable, takes coins, has a video display and is not flagged mechanical; gambling boards (by driver folder, driver file or words such as poker, slot, bingo in the title) and mahjong boards are categorised separately and left out of the headline counts. Working means MAME does not flag it MACHINE_NOT_WORKING (listxml emulation="preliminary"). Not-working sets are kept in the data but excluded from every default count.
  • MiSTer side. Every MRA (plus the NeoGeo core's romsets.xml) in the official distribution, JTCORES (jotego), Coin-Op Collection, OngoGablogian's MiSTer_Ongo database, the per-core releases/ folders, the developer downloader databases (MeatCores, Slop Cores, kuzecores, jlrh, arcfpga, blahm1d; cores published only as builds, such as Patreon releases, count through the MRAs their database ships), a hand-kept list of repositories nobody indexes yet, and the registry kept by alamone/fpga-verified-against. An MRA's <setname> is the MAME set it loads; its <rbf> names the core.
  • Dates. Each repository is cloned without file contents and git log gives the day each MRA file was first committed. The earliest date across every source is the date a set became available; a title (MAME parent set plus its clones) takes the earliest of its sets. Where a repository's history was squashed (jotego's jtbin in May 2024, the official distribution starts September 2021) the per-core repository history fills in; where no history exists at all the core's latest build date is used and marked approximate.
  • Genre. From MAME's category file catver.ini first (a current copy at data/catver.ini if present, else the copies libretro vendors), then the MiSTer Arcade Database, then the MRA's own <category> tag. A set without a category takes its parent's, else a clone's. The raw strings (135 spellings across sources) are remapped to a short common list by data/genre_map.json, which is meant to be edited. The raw value and its source show in the title's tooltip.
  • BIOS sets (MAME isbios, e.g. "Acclaim ZN-1", "Neo-Geo") are not games and are left out entirely.
  • Titles vs sets. A title is a MAME parent set with all its clones. It counts as covered when any of its sets loads on any core. The burndown therefore shows titles, not individual ROM sets.

Caveats

  • "On MiSTer" means an MRA exists; it says nothing about how well the core runs the game.
  • The MAME total is for one MAME version. Sets MAME added after a core shipped show up as covered from the MRA date, so the early part of the curve is measured against today's MAME, not the MAME of the time.
  • Cores that predate the MRA format (2018 to mid-2019) are dated by their first MRA, which is later than the core's first release.
  • Category heuristics are rough: some gambling and mahjong boards live in ordinary driver folders and count as arcade.

Data

coverage.json holds every title, set, core and date on this page. summary.json is the roll-up (meta, cores, drivers, unmatched sets).
